Codebase Context

The setup

  • One shared git checkout, ~/code/tasks, read/written by every wb session regardless of repo.
  • wb.sh (~2242 lines) mediates file writes only — it runs zero git commands against TASKS_DIR (grep-confirmed across every git -C call site).
  • Every dangerous git command in the incidents was typed in an agent's own shell — not through any wb.sh code path.

Three incidents

  • handoff.sh's own concurrent-invocation race — flagged, never fixed.
  • git reset --hard origin/development rewound past another session's unpushed commits — caught by luck.
  • Same failure mode, days later — silently discarded a committed update, recovered only because GC hadn't run yet.

Confirmed code gaps

  • wb_set_frontmatter: whole-file read → awk → rename, no lock, no staleness check — textbook TOCTOU.
  • wb_seed_task / cmd_done chain 5-6 sequential calls to it — not one transaction.
  • Zero flock/lockfile/PID-file anywhere; no dead-session detection beyond a bare tmux has-session check.

External signal

  • Claude Code ships an official PreToolUse hook that hard-blocks a matched command — survives --dangerously-skip-permissions.
  • Git's reference-transaction hook can genuinely veto a ref update (verified against man githooks, not recalled).
  • flock auto-releases on any process death — no TTL/heartbeat needed.
  • Bare-repo + per-agent-worktree is the dominant 2026 pattern for many-agents-one-repo.

Three-layer hook stack for git-history-safety

Axis: git-history-safety
Confidence 90%Complexity Medium

Agent-side hook blocks the command before it runs · git-side hook vetoes it even if the agent hook is bypassed · a paved path removes the reason to hand-type it at all.

// ~/.claude/settings.json
{
  "hooks": { "PreToolUse": [{
    "matcher": "Bash",
    "hooks": [{ "type": "command",
      "command": "~/.claude/hooks/guard-tasks-dir.sh" }]
  }] }
}
# guard-tasks-dir.sh
cwd=$(jq -r '.tool_input.cwd')
cmd=$(jq -r '.tool_input.command')
[[ "$cwd" == "$HOME/code/tasks"* ]] || exit 0
echo "$cmd" | grep -Eq 'reset +--hard|--force|clean +-f' &&
  { echo '{"decision":"block"}'; exit 0; }
# ~/code/tasks/.git/hooks/reference-transaction
[ "$1" = prepared ] || exit 0
while read -r old new ref; do
  git merge-base --is-ancestor "$old" "$new" || {
    echo "refuse: $ref would lose commits" >&2
    exit 1
  }
done

Why

  • All 3 incidents were hand-typed — wb.sh makes 0 git calls here.
  • Reference-transaction veto confirmed real via man githooks.
  • destructive_command_guard is working prior art for the agent-side hook.

Cost

  • Refuse-condition must be scoped carefully (false positives elsewhere).
  • Agent hook covers Claude Code only — git hook covers a raw terminal too.

Per-agent worktree isolation of TASKS_DIR

Axis: enforcement-topology
Confidence 75%Complexity High

Give TASKS_DIR the same per-repo worktree pattern cmd_new already runs for code repos — each session gets its own worktree, fast-forward merge-back on wb pause/wb done.

The central fork: three mutually exclusive answers to where write access to TASKS_DIR lives. A guards today's shape; B and C remove the shared-write surface, at rising structural cost.

Why

  • cmd_new (wb.sh:318-330) already proves this pattern for code repos.
  • Bare-repo + per-agent-worktree is 2026's dominant multi-agent pattern (371 worktrees cited).

Cost

  • Reopens the "always-current store" tension — wb board shows "as of last sync."
  • Needs a real merge-back design, not just worktree-add.

Single-writer intent-queue daemon

Axis: enforcement-topology
Confidence 55%Complexity High

One process owns every mutation; sessions append intents instead of writing directly. See topology C above.

# ~/code/tasks/.intent-log (O_APPEND, atomic under PIPE_BUF)
2026-07-11T14:01Z set dotfiles--feat-x status doing
2026-07-11T14:02Z set dotfiles--feat-x status reviewing

# daemon loop
tail -F .intent-log | while read -r ts op file key val; do
  wb_set_frontmatter_batch "$file" "$key=$val"
  git add "$file" && git commit -q -m "sync: $key=$val"
done

Why

  • 5 whole-file-replace call sites collapse into 1 code path.
  • MMO server-authoritative-transactions lesson: don't trust client-submitted state.

Cost

  • Verifier flagged scope stretch (100-agent / cross-machine framing overshoots reality).
  • New persistent process to keep reliable; exclusive with idea 2.

Atomic multi-field write primitive

Axis: file-write-concurrency
Confidence 92%Complexity Low

Collapse sequential per-field writes into one atomic rename, guarded by a generation nonce.

# before — 2 renames, race window between them
wb_set_frontmatter "$f" status done
wb_set_frontmatter "$f" closed "$(date +%F)"

# after — 1 rename, aborts if rev: moved
wb_set_frontmatter_batch "$f" --expect-rev "$rev" \
  status=done closed="$(date +%F)"

Why

  • Both bugs confirmed directly in code, not inferred.
  • Also unblocks the in-flight parent/child feature's dual-file update.

Cost

  • New abort-and-retry contract for every caller.
  • File-level only — doesn't touch git-history races.

Event-sourced append-only frontmatter

Axis: file-write-concurrency
Confidence 65%Complexity Medium

Alternative philosophy to idea 4: never overwrite, fold over an append-only log instead.

## Handoffs
- 2026-07-11T14:01Z status: doing (dotfiles-feat-x)
- 2026-07-11T14:02Z status: reviewing (dotfiles-feat-x)
- 2026-07-11T14:02Z status: done (be-monorepo-fix-y)

Why

  • Reuses the README's own ## Handoffs convention — not foreign.
  • wb_reconcile_apply already reopens-not-merges-blind — this generalizes that.

Cost

  • Real schema change — touches the reader and wb board's status column.
  • Needs explicit buy-in before implementation.

Full contention-UX package

Axis: session-lifecycle
Confidence 88%Complexity Low

Per-file flock + fail-fast holder-named message + reuse handoff.sh's liveness check + halt-and-ask on genuine ambiguity.

# wb_with_lock
wb_with_lock() {
  local f="$1"; shift
  exec {fd}>"$f.lock"
  flock -w 1 "$fd" || {
    echo "waiting on $(cat "$f.lock.owner")" >&2; return 1; }
  echo "$WB_SESSION" > "$f.lock.owner"
  "$@"
}

Why

  • flock auto-releases on any process death — answers staleness for free.
  • handoff.sh:185-196 already implements the liveness check being reused.

Cost

  • Doesn't prevent a write conflict alone — pair with idea 4 or 5.
  • Message wording is a small but real design surface.
7

Belt-and-suspenders recovery layer

Axis: git-history-safety
Confidence 95%Complexity Low

Ships regardless of which other idea wins — turns "we got lucky" into "this always works."

git -C ~/code/tasks config gc.auto 0
git -C ~/code/tasks config gc.reflogExpire never
git -C ~/code/tasks config gc.reflogExpireUnreachable never

# snapshot before any reset/rebase/force-push:
git -C ~/code/tasks branch \
  "refs/safety/$(hostname)-$(date +%s)" HEAD

Why

  • Incident 3 recovered only by luck — gc.reflogExpire/gc.auto confirmed unset today.
  • Strictly improves every other option's worst case.

Cost

  • Prevents nothing by itself — recoverability only.
  • refs/safety/* needs eventual cleanup (low urgency).
