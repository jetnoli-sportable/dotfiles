Jira emit — the careful one

⏱ ~20–25 min · live Jira
🌱

This is the only pass that creates real tickets you'd delete by hand afterward — so take it slow, start with the dry run, and use throwaway [wb-emit-test] titles. The full step-by-step lives in the original Jira checklist if you want every detail. The “don't run yet” banner stays until this pass is done.

  • Connect Jira + do a dry run (no tickets created)
    Reconnect the Atlassian MCP, then run /wb-jira-create on a throwaway task and close the buffer unchecked — it should report a clean no-op with zero writes. Good confidence-builder.
  • Create one flat ticket
    Standalone task, blank parent → one SFB ticket, and the ticket URL is stamped back into the task's jira: field.
  • Create a family
    A coordinator + child → coordinator ticket first, child “Relates”-linked to it, both stamped. (Bonus: try an existing SFB-XXXX as the parent — no new parent ticket is made.)
  • Retry is safe — the important one
    Re-run on the same family → it finds and reuses the existing tickets, creating zero duplicates. Also: a task already carrying jira: is skipped, never re-created.
  • Write-back behaves
    wb jira-set <task> <same-url> → no-op; <different-url> → refuses and changes nothing.
  • Try the SW project too
    Set Project: SW in the buffer → lands as SW-<n>, and an SFB-only type is rejected before anything is created. (If the connection drops mid-run, it stops cleanly before creating anything.)
  • Wrap up: delete test tickets, drop the banner
    Delete the throwaway [wb-emit-test] tickets in Jira, then remove the “don't run yet” banner from the wb-jira-create skill. That closes out #32.
