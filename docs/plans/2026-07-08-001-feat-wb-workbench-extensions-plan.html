Key technical decisions

resolved — 6-tab model

/board is six status-based tabs, not a composable 2-axis filter: All / In Progress / Upcoming / Paused / Deferred / Unclassified. Each tab is literally "is this task's status in the tab's set." My original combined-algorithm synthesis was rejected outright.

resolved — catch-all

Unclassified is a genuine catch-all — unmapped/future status values, plus (the concrete case today) a git worktree on disk with no task file at all, reusing U6's worktree-scan. Considered and rejected: splitting doing by live-session presence.

resolved — new

Live-session state is a per-row badge (icon + session name), not a tab axis — every row in every tab can carry one, reusing the picker's existing session lookup.

resolved

wb pause does NOT kill the session — only worktree teardown is skipped. wb done is also changing to stop killing the session — a direct instruction, not new scope, touching already-shipped behavior.

resolved — synthesis

"Merge with task" survivor UI — paired sub-checkboxes naming each candidate file, with a most-recently-active pick pre-checked as the default. Rejected extremes: pure free text (typo-prone) and a fully silent automatic pick (repeats the original problem).

decided

/board's tabs are CSS-only, zero JavaScript — a single static file with no backend can't re-invoke the shell per click.

decided, from mockups

Layout: compact table (mockup A over cards/kanban) — matches docs/roadmap.md's existing table convention, doesn't reopen the composable filter model kanban would have. Refined after seeing it rendered: drill-down is an anchor jump-link to a detail section below the table, not inline <details> expansion.
